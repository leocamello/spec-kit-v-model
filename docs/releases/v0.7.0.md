# v0.7.0 — Bridge Commands & Pre-v0.8.0 Stabilization

> **Release theme**: close the gap between V-Model artifacts and executable implementation by shipping `/speckit.v-model.{plan,tasks,implement}` bridge commands, then harden every newly-exposed surface against the issues surfaced by the pre-v0.8.0 architectural audit and red-team review.

## Headline features

### 1. Bridge commands — `plan`, `tasks`, `implement`

Three new commands wrap (and harden) the corresponding `spec-kit-core` commands so that V-Model artifacts feed directly into deterministic, gated implementation:

| Command | Wraps | Adds |
|---|---|---|
| `/speckit.v-model.plan` | `/speckit.plan` | V-Model-enriched `plan.md` synthesis, pinned-schema validation, structured run summary |
| `/speckit.v-model.tasks` | `/speckit.tasks` | TDD-ordered task decomposition aware of `unit-test.md` / `integration-test.md` / `system-test.md` / `acceptance-plan.md`; per-task `Implements`-directive headers |
| `/speckit.v-model.implement` | `/speckit.implement` | Pre-flight `run-v-model-gate.sh`; four-level test generation; sentinel-managed splicing into existing sources; `Implements`-directive hallucination guard; post-implement trace hook |

### 2. Validator hardening (MF-1 through MF-7 from the stabilization blueprint)

Eight additional validators or validator enhancements landed in the v0.7.x stabilization sprint:

| ID | Script | Purpose |
|---|---|---|
| MF-1 | `scripts/{bash,powershell}/setup-{plan,tasks,implement}.{sh,ps1}` | Thin V-Model-aware wrappers around the upstream `setup-*` scripts; surface `VMODEL_DIR` to the bridge prompts. |
| Stabilization fix | `scripts/{bash,powershell}/validate-implements-ids.{sh,ps1}` | New `--canonical / --scan / --changed-only` flags. The hallucination guard now scans the **repo root** (not just the V-Model dir) and intersects with `git diff` so the actually-generated source under `src/` and `tests/{unit,integration,system,acceptance}/` is in scope. |
| MF-3 | `scripts/bash/build-matrix.sh` | Same-dir `mktemp` + `EXIT/INT/TERM` trap. No more `/tmp` writes; concurrent matrix builds are now safe. |
| MF-4 | `scripts/{bash,powershell}/validate-core-schema.{sh,ps1}` | Three-pass validation: existence → ordering → wedge rejection. The order/exact-set of pinned H2s is now mechanically enforced via `diff -u`. |
| MF-5 | `scripts/{bash,powershell}/splice-managed-regions.{sh,ps1}` | BEGIN/END id-match enforcement (exit 2), duplicate-id detection (exit 2), `--region-from <regions-file>` per-region payload mode, `diff -u original spliced` on stderr on every successful run for audit-trail capture. |
| MF-6 | `scripts/{bash,powershell}/validate-artifact-status.{sh,ps1}` | Approval-status gate. Wired as the **first** sub-validator in `run-v-model-gate.sh`. Default: every canonical V-Model artifact must carry `**Status**: Approved`. Configurable via `--required-status`. |
| MF-7 | `scripts/{bash,powershell}/validate-domain-profile.{sh,ps1}` + `v-model-config.yml.example` | Domain overlay validator. Absent config = non-fatal SKIP; present-and-invalid = fatal. The example file documents the three valid `domain:` values: `iso_26262 / do_178c / iec_62304`. |

`run-v-model-gate.sh` is now an 8-stage pipeline: `status → domain → matrix → requirement-coverage → system-coverage → architecture-coverage → module-coverage → hazard-coverage`.

### 3. Prompt + docs alignment (MF-9 + MF-10)

- `commands/plan.md` no longer advertises a direct `Implement Plan` handoff to `speckit.v-model.implement`. The V-Model lifecycle is `plan → tasks → implement`; jumping straight from plan to implement skips the TDD-ordered task decomposition the rest of the system expects.
- The new **[Compliance & Hybrid Modes](../../README.md#compliance--hybrid-modes)** section in the README explicitly distinguishes the **compliant** end-to-end V-Model bridge from the **hybrid** mode (feeding a V-Model `tasks.md` to core `/speckit.implement`). Hybrid mode is now documented as a prototyping-only escape hatch, not a feature.

## Compliance & Hybrid Modes

See the README's [Compliance & Hybrid Modes section](../../README.md#compliance--hybrid-modes) for the canonical statement.

In short: a build that ran core `/speckit.implement` against a V-Model `tasks.md` is **not** evidence of V-Model compliance — the deterministic gates left no record because they were not invoked. The compliant path runs `/speckit.v-model.implement` end-to-end, exercising `run-v-model-gate.sh`, the `Implements`-directive hallucination guard, and the trace post-hook on every change.

## Audit-noted limitations (deferred to v0.8.0)

The pre-v0.8.0 audit identified several legitimate hardening opportunities that did not fit the v0.7.x patch envelope. They are tracked as Epics in the v0.8.0 backlog (see `.tmp/pre-v0.8.0-audit/ultimate-stabilization-blueprint.md`):

| Epic | Theme | What v0.7.0 does NOT enforce |
|---|---|---|
| **EPIC-1** | `compliance_mode: strict` profile | A repo-wide flag that flips hook `optional: true` → `false` and makes hybrid mode mechanically detectable in CI. v0.7.0 documents the distinction but does not enforce it. |
| **EPIC-2** | Sealed baseline + signed run attestation | Append-only ledger, `.specify/v-model/baseline.lock`, `validate-task-provenance.sh`. v0.7.0 has no defence against a `tasks.md` whose source artifacts have drifted post-generation. |
| **EPIC-3** | Immutable compliance-artifact protection | `before_implement` / `after_implement` snapshot diff. v0.7.0 does not block `implement` from mutating canonical V-Model artifacts. |
| **EPIC-4** | Semantic `Implements`-directive validation | The hallucination guard validates that cited IDs **exist**; v0.8.0 adds path/symbol/reachability checks (MOD→ARCH→SYS→REQ via the trace matrix). |
| **EPIC-5** | Single `v-model verify` aggregator + SARIF/JSON | Unified machine-readable output for CI. v0.7.0 emits human-readable per-validator stdout/stderr only. |
| **EPIC-6** | Authorized managed regions | Region IDs encode authorized V IDs (`id="MOD-003:calculate-risk"`); splicer cross-validates against `module-design.md`'s `Target Source File(s)`. v0.7.0 ships id-match + duplicate-detection (MF-5) but not the cross-artifact authorization check. |
| **EPIC-7** | Deterministic golden-output e2e fixtures | LLM-judge demoted from primary release evidence to advisory regression detector. |
| **EPIC-8** | Package-install smoke test | CI job that asserts all 17 commands + 4 hooks register after a clean install. |
| **EPIC-9** | Strict prompt-injection containment | Net-new linter for prompt-injection patterns in V-Model artifacts. |
| **EPIC-10** | Reviewer/signoff schema | Per-artifact `reviewers:` and `signoff:` fields validated against domain-specific minimums (MF-6 ships only the binary `Approved` check). |

### Pre-existing artifact gap (deferred to v0.8.0)

- **`specs/007-bridge-commands/v-model/architecture-design.md` cross-cutting modules ARCH-008, ARCH-014, ARCH-016** lack dedicated ITP coverage. `validate-architecture-coverage.sh` flags this as a coverage gap on the 007 dogfood feature. Consumers running `run-v-model-gate.sh` against the 007 feature directory will see this single inner validator fail; the gate is otherwise green. Tracking: [F-024 in `.tmp/d0-doc-audit-report.md`].

## Migration notes

- **Existing repositories** with `**Status**: Draft` headers on canonical V-Model artifacts will see `run-v-model-gate.sh` fail at the new MF-6 status validator. Either flip the status to `Approved` (the intended workflow) or invoke the validator directly with `--required-status Draft --required-status Approved` while migrating.
- **`v-model-config.yml`**: if you have a previous file referencing `domain: automotive | medical | aerospace` (industry vernacular from earlier docs), rename to `iso_26262 | do_178c | iec_62304` (standard IDs matching the directories under `commands/overlays/`). The validator's error message will tell you exactly which value to use.
- **Splicer callers**: existing single-payload-for-all-regions invocations remain byte-identical on stdout. The new `diff -u` emission goes to **stderr** only — capture it (e.g. `2>> tests/.splicer-diffs.log`) for audit-trail evidence; suppress it (`2>/dev/null`) only if you do not need that evidence.
- **Bridge commands**: if you have CI that invokes `/speckit.plan` / `/speckit.tasks` / `/speckit.implement` directly on a V-Model repository, consider switching to the `/speckit.v-model.*` variants to pick up the gates and the hallucination guard. The hybrid path remains supported for prototyping (see Compliance & Hybrid Modes).
